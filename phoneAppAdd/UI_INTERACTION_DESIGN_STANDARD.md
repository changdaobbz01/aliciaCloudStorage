# Alicia Cloud phoneAppAdd UI/交互设计标准

## 1. 可行性结论

`phoneAppAdd` 可以作为一个独立 Android 工程启动，功能一比一复刻当前 `phoneApp` 的可行性高。推荐方式是复制当前 `phoneApp` 的工程骨架、数据层、Repository、API DTO、ViewModel 状态机和权限处理，只替换 UI Shell、组件体系和视觉资源。这样能最大限度复用已经验证过的登录、文件管理、分享识别、预览、上传、下载、传输管理、更新检查等能力。

签名需要单独确认。当前 `phoneApp/app/build.gradle.kts` 没有显式 release signingConfig，仓库内只看到已产出的 release signed APK，没有看到 keystore 或签名属性文件。因此：

- Debug 包：如果继续用同一台机器默认 debug keystore，签名通常能保持一致。
- Release 包：必须复用当前正式包的同一份 keystore、alias、storePassword、keyPassword 或同一套外部 `apksigner` 流程。
- `phoneAppAdd` 当前按并行体验版处理，使用独立 `applicationId = "com.alicia.cloudstorage.phone.add"`，可以和当前 `phoneApp` 同时安装。
- 因为并行体验版不会覆盖正式包，即使签名相同，也会被 Android 识别为另一个应用。

建议在设计验证阶段保持独立 `applicationId`，等新 UI 确认要替换正式版时，再切回正式 `applicationId` 并走正式签名/升级验证流程。

## 2. 参考图风格定位

参考图整体接近夸克网盘风格：轻量、白底、黑色粗标题、蓝色操作强调、大圆角卡片、低阴影、强留白、底部导航固定。它和当前 `phoneApp` 的机甲风完全不同，应该独立建立一套设计系统，不建议在现有机甲组件上继续堆样式。

设计关键词：

- 清爽白底
- 强留白
- 大圆角
- 黑色粗字
- 蓝色主操作
- 轻拟物图标
- 卡片承载信息
- 弹窗下沉
- 快捷入口网格化
- 列表操作弱化，批量操作集中化

## 3. 主色系

主背景：

- 页面背景：`#F7F8FB` 或 `#F8F9FC`
- 卡片背景：`#FFFFFF`
- 底部导航背景：`#FFFFFF`
- 遮罩：`rgba(0, 0, 0, 0.56)`

品牌蓝：

- 主蓝：`#0B6BFF`
- 主蓝高亮：`#147BFF`
- 渐变蓝起点：`#1A8CFF`
- 渐变蓝终点：`#005BFF`
- 浅蓝选中底：`#EAF3FF`
- 筛选选中底：`#DDEAFF`

文本：

- 一级标题：`#15171D`
- 正文：`#22252B`
- 次级文本：`#8B8F99`
- 弱提示：`#B1B5BE`
- 分割线：`#EEF0F4`

状态色：

- 成功：`#16B56F`

## 4. 字体与排版

字体使用系统默认中文字体，不引入额外字体包，确保渲染稳定。

标题规范：

- 页面大标题：28-32sp，FontWeight.Black，颜色 `#15171D`
- 二级卡片标题：18-22sp，FontWeight.Bold
- 列表文件名：15-17sp，FontWeight.Bold
- 底部导航文字：11-12sp，FontWeight.Bold
- 次级说明：12-14sp，FontWeight.Medium，颜色 `#8B8F99`

排版原则：

- 不使用负 letter spacing。
- 标题最多 1 行，超出省略。
- 文件名列表最多 1 行，宫格最多 2 行。
- 元信息统一格式：`yyyy/MM/dd HH:mm  文件大小`。
- 同一页面横向边距建议 16-20dp。
- 卡片内部间距建议 16-20dp。

## 5. 页面布局标准

所有一级页面遵循以下骨架：

1. 顶部标题区
2. 搜索框
3. 主内容卡片或列表区域
4. 悬浮新增按钮
5. 底部导航

安全区：

- 顶部适配状态栏，内容不贴边。
- 底部导航适配 navigation bar。
- 弹窗使用系统 inset，底部至少留 8dp。

页面背景：

- 不再使用机甲纹理、九宫格切片、深色网格背景。
- 页面整体保持浅灰白背景，卡片和弹窗用白色。

卡片：

- 首页功能卡片：圆角 20-24dp。
- 列表内容卡片：顶部圆角 24-28dp，可承载排序、筛选和文件列表。
- 搜索框：圆角 16-18dp，高度 52-56dp。
- 卡片阴影非常轻，优先使用色块层次而不是重阴影。

## 6. 底部导航

参考图固定 4 个 Tab：

- 首页
- 文件
- 传输
- 会员

当前项目能力映射建议：

- 首页：复用当前 Home 概览、最近文件、空间使用。
- 文件：复用当前文件管理、回收站入口、搜索、上传、新建、预览、下载。
- 传输：复用当前传输管理，包含上传和下载队列。
- 会员：当前后端没有会员体系，建议映射为“我的/账号”页；视觉文案可先用“我的”，不要假造会员功能。

底部导航风格：

- 白底固定栏，高度 68-78dp。
- 图标为黑色线性/面性混合，选中状态图标填充更重。
- 文字固定显示，不只显示选中项。
- 选中色不必全蓝，参考图是黑色实心图标+黑色文字。

## 7. 顶部栏

首页顶部：

- 左侧大标题：`Alicia 云盘` 或用户配置的产品名。
- 右侧双按钮胶囊：扫码/设置/关闭等入口。当前 API 不支持扫码上传时，扫码入口可不展示。

文件页顶部：

- 根目录页标题：`文件`
- 子目录页标题：当前文件夹名，左侧返回箭头。
- 右侧：更多 `...`、关闭/账号入口或设置入口。

传输页顶部：

- 标题：`传输列表`
- 右侧：设置图标 + 关闭/返回入口。

交互：

- 顶部搜索框点击进入搜索态。
- 子目录页返回箭头只退一级目录。
- 关闭按钮如果处在主 App 内不建议退出 App，可返回首页或关闭当前浮层。

## 8. 搜索

搜索框视觉：

- 高度 52-56dp。
- 白色圆角背景。
- placeholder：`搜索网盘文件`。
- 左侧不放图标，右侧放黑色搜索图标，尺寸 30-34dp。

搜索行为：

- 首页搜索：全局搜索。
- 文件页搜索：默认当前目录搜索，并提供“全局搜索”切换。
- 搜索结果仍使用文件列表/宫格组件，不另做弱样式列表。
- 清空关键字后回到当前目录。

当前 API 支持度：

- 当前项目已区分首页全局搜索和文件页当前目录搜索，可直接复用。

## 9. 首页设计

首页模块：

- 顶部搜索框。
- 空间/账号卡片：展示头像、已用空间、总容量。
- 文件分类快捷入口：视频、相册、文档、音频、压缩包、云收藏、快传、录音纪要、回收站、隐私空间。
- 最近文件卡片：按类型分组展示最近文件。
- 悬浮 `+` 上传按钮。

当前能力映射：

- 视频、相册、文档、音频、压缩包：可根据文件扩展名和 MIME 做筛选入口。
- 回收站：已支持。
- 云收藏、快传、录音纪要、隐私空间：当前 API 不支持完整业务。建议先作为禁用入口或隐藏；如果保留，需要显示“暂未开放”。
- 最近文件：当前 Home recentNodes 可支持。

优化建议：

- 首页的分类快捷入口不要跳营销页，直接进入文件筛选结果。
- 空间卡片可去掉会员营销语，改为真实容量升级提示。
- 当前用户非管理员时不展示团队/账号管理入口。

## 10. 文件页列表视图

列表项结构：

- 左侧缩略图/文件类型图标，尺寸 44-56dp。
- 中间：文件名 + 元信息。
- 右侧：圆形选择框。
- 点击文件夹 Item 主体进入文件夹。
- 点击文件 Item 主体打开预览。
- 右侧选择框只负责选择，不触发打开。

元信息：

- 文件：`更新时间  文件大小`
- 视频可追加：`未观看`，但当前 API 没有观看状态，先不展示。
- 文件夹：`更新时间`，大小可不显示。

排序区：

- 左侧：`综合排序` + 下箭头。
- 右侧：列表/宫格切换图标、筛选图标。

当前能力映射：

- 文件夹进入：已支持。
- 文件预览：图片、文本、PDF、视频、音频已支持。
- 列表/宫格切换：当前可用本地状态实现，不需要后端。
- 排序：当前前端/客户端可本地排序；后续如需分页大目录再扩 API。

## 11. 文件页宫格视图

宫格布局：

- 2-3 列自适应，手机竖屏建议 3 列。
- 缩略图区域固定宽高比，图片裁切填充，文件夹和通用文件居中图标。
- 文件名最多 2 行，居中。
- 元信息在文件名下方，居中，颜色弱化。
- 右上角圆形选择框覆盖在卡片内部。

交互：

- 点击文件夹卡片主体进入文件夹。
- 点击文件卡片主体预览。
- 点击选择框切换多选。
- 长按也可进入多选，但不能作为唯一入口。

## 12. 多选模式

参考图中选择框常驻，所以建议不做强烈的“进入多选态”切换，而是采用轻量多选：

- 每个 Item 右侧常驻空心圆。
- 点击空心圆选中后变蓝色实心勾。
- 选中任意项目后底部出现批量操作栏。
- 页面标题区可显示 `已选 N 项`，右侧提供取消/全选。

批量操作栏：

- 下载
- 移动
- 分享
- 删除
- 更多

回收站批量操作：

- 恢复
- 彻底删除
- 取消选择

安全规则：

- 删除和彻底删除必须二次确认。
- 批量下载文件夹必须走后端 ZIP 接口。
- 批量下载失败保留传输任务并提供重新下载。

当前 API 支持度：

- 批量下载、移动、删除、恢复、彻底删除、分享基本支持。
- 分享保存选择项已支持。

## 13. 操作入口

悬浮 `+`：

- 位置：文件页/首页右下方，距离底部导航 90-110dp。
- 尺寸：64-72dp。
- 颜色：蓝色径向或线性渐变。
- 图标：白色 `+`，尺寸 32-36dp。

点击后弹出底部操作面板：

- 第一组：离线下载，可包含添加磁力链、添加 BT 任务。
- 第二组：上传手机文件，包含相册、文档、压缩包、安装包、音频、其他文件、新建文件夹。

当前 API 支持度：

- 上传文件：支持。
- 新建文件夹：支持。
- 相册/文档/压缩包/安装包/音频：可通过 Android picker MIME type 实现分类选择。
- 添加磁力链、添加 BT 任务：当前 API 不支持，建议禁用或隐藏，不能做假成功。

## 14. 单文件/文件夹操作

文件点击主体：

- 图片/文本/PDF/视频/音频：打开预览。
- 不支持预览：打开操作底部面板。

文件夹点击主体：

- 进入文件夹。

更多操作面板：

- 文件：预览、下载、分享、重命名、移动、删除。
- 文件夹：进入、下载文件夹、分享、重命名、移动、删除。
- 回收站：恢复、彻底删除。

下载：

- 单文件走签名 URL 下载。
- 文件夹走 ZIP 打包下载。
- 下载任务进入传输列表。
- 失败任务在 Web 和 Android 均显示重新下载。

## 15. 传输列表

页面结构：

- 标题：`传输列表`
- 顶部 Tab：上传、下载、云收藏、转换/解压。
- 当前 API 支持上传和下载，云收藏、转换/解压暂不支持。
- 顶部提示卡：可改为真实提示，如“传输任务仅保存在本机”。
- 状态筛选：全部、已完成、进行中、失败。

任务 Item：

- 左侧：文件缩略图或类型图标。
- 主标题：文件名。
- 副标题：大小、方向、状态。
- 进度条：蓝色进行中，绿色成功，红色失败。
- 失败任务：显示失败原因和 `重新下载`/`重新上传`。

当前能力建议：

- 下载失败必须提供重新下载。
- 上传失败也建议提供重新上传，当前 Web 已有上传重试，Android 可以后续补齐上传失败单项重试。
- 传输记录可先保存在内存；如果要跨启动保存，需要 DataStore/Room，但不能持久化 token 或签名 URL。

## 16. 筛选弹窗

弹窗形式：

- Bottom sheet。
- 遮罩压暗背景。
- 顶部圆角 28-32dp。
- 高度根据内容自适应，最多 70% 屏高。

内容：

- 标题：`筛选设置`
- 视图：列表视图、宫格视图。
- 筛选：全部、云收藏视频、备份图片、分享转存、我上传的、我扫描的、我解压缩的。
- 底部按钮：重置、确定。

当前 API 支持度：

- 列表/宫格：支持本地状态。
- 全部：支持。
- 我上传的、分享转存、我扫描的、我解压缩的、云收藏视频、备份图片：当前 API 没有来源字段，建议不展示或置灰。
- 可替代为当前能力筛选：全部、文件夹、图片、视频、音频、文档、压缩包、其他。

## 17. 弹窗与确认

通用弹窗：

- 使用白底大圆角。
- 标题 20-24sp，加粗。
- 正文 14sp，灰色。
- 主按钮蓝底白字。
- 次按钮浅灰底黑字。
- 危险按钮红色文本或红色描边。

底部操作面板：

- 优先用于文件操作、上传入口、筛选。
- 面板不使用复杂背景图。
- 每个操作是大点击区域，至少 56dp 高。

二次确认：

- 删除文件
- 彻底删除
- 退出登录
- 切换后端环境
- 覆盖敏感设置

## 18. 图标风格

图标原则：

- 统一使用圆润线性图标或轻拟物蓝色文件类型图标。
- 主功能分类图标可使用蓝色渐变面性图标。
- 底部导航使用黑色线性图标，选中状态加粗或填充。
- 文件类型图标使用固定颜色：图片蓝/青，视频蓝，PDF 红，压缩包蓝，文件夹浅蓝。

避免：

- 不再使用机甲金属边框。
- 不再使用发光描边。
- 不再使用深色底纹。
- 不再混用过多图标库。

实现建议：

- Compose 内优先使用 `material-icons-extended`。
- 文件类型图标可使用自绘 Compose 组件，避免大量 PNG 资源。
- 图片缩略图使用 Coil。

## 19. 登录与账号页

登录页风格：

- 白/浅灰背景。
- 产品名大标题。
- 手机号、密码输入框使用大圆角白色卡片。
- 登录按钮蓝色满宽。
- 错误提示使用 Snackbar 或表单下方红字。

账号页建议：

- 如果底部第 4 Tab 叫“会员”，但实际无会员能力，内容必须落在账号能力上。
- 推荐命名为“我的”，避免误导。
- 展示头像、昵称、手机号、空间使用、当前环境、版本更新、退出登录。

## 20. 分享详情

当前分享详情可保留底部弹窗形式，但视觉改成白底风格：

- 顶部显示分享者、分享标题、权限。
- 文件夹默认收起。
- 如果允许保存，显示选择框和保存选中按钮。
- 不提供分享详情单文件直接下载按钮，保持当前业务要求。
- 保存成功后跳转文件页。

## 21. 文件预览

预览页：

- 顶部白色工具栏。
- 图片：黑/白背景可切换，默认黑色沉浸。
- PDF：白底分页预览。
- 文本：白底等宽/系统字体，顶部显示编码提示。
- 视频/音频：系统播放器控件即可。

操作：

- 下载
- 分享
- 更多
- 关闭/返回

## 22. 加载、空状态和错误

加载：

- 页面级 loading 使用轻量转圈，不遮整个页面太久。
- 列表刷新可使用下拉刷新。
- 上传/下载必须进入传输列表显示进度。

空状态：

- 使用浅灰图标 + 简短文案。
- 文件空状态：`暂无文件`
- 传输空状态：`暂没有上传记录` / `暂没有下载记录`
- 搜索空状态：`没有找到相关文件`

错误：

- 普通错误用 Snackbar。
- 任务错误保留在任务 Item 内。
- 权限/登录失效引导重新登录。

## 23. 动效

动效保持克制：

- Bottom sheet：标准上滑。
- Tab 切换：短横线滑动或淡入。
- 列表项选择：圆形选择框颜色过渡。
- 上传/下载进度：线性进度条。
- FAB：轻微缩放反馈。

避免：

- 大面积粒子/发光。
- 复杂背景动画。
- 文件列表滚动时卡片漂浮。

## 24. 当前 API 能力映射

可一比一实现：

- 手机号密码登录
- 首页概览
- 当前目录/全局搜索
- 文件夹浏览
- 文件上传
- 新建文件夹
- 文件预览
- 单文件下载
- 文件夹/多选 ZIP 下载
- 下载管理
- 上传管理
- 下载失败重新下载
- 分享创建
- 分享链接识别
- 分享选中保存
- 回收站恢复/彻底删除
- 账号信息和正式服务接入
- App 更新检查

需要降级或隐藏：

- SVIP/会员购买
- 云收藏
- 快传

- 隐私空间加密
- 离线磁力链
- BT 任务
- 转换/解压

建议替代：

## 25. 工程实现建议

推荐目录：

```text
phoneAppAdd/
  settings.gradle.kts
  build.gradle.kts
  gradle/
  app/
    build.gradle.kts
    src/main/
      AndroidManifest.xml
      java/com/alicia/cloudstorage/phone/
        data/
        ui/
          KuakeStyleApp.kt
          KuakeTheme.kt
          KuakeComponents.kt
          screens/
          sheets/
```

实现策略：

- 第一阶段复制 `phoneApp` 可运行工程到 `phoneAppAdd`。
- 第二阶段保留 `data`、`Models`、`AliciaCloudApi`、`AliciaRepository`、`MainViewModel` 的核心状态能力。
- 第三阶段新建 `KuakeTheme`、`KuakeComponents`，替换 `AliciaCloudApp` 的 UI。
- 第四阶段逐页迁移：登录、首页、文件、传输、我的、分享弹窗、预览弹窗。
- 第五阶段真机截图比对参考图，逐项调间距、字体、圆角、按钮和弹窗。

低耦合要求：

- 不把颜色和尺寸散落在页面里，统一放 Design Tokens。
- 文件类型识别、日期格式化、大小格式化放工具层。
- 列表/宫格共享同一份节点点击和选择逻辑。
- 弹窗组件统一封装。
- 业务状态不因 UI 风格变化而重写。

## 26. 签名与发版要求

如果作为当前 App 的新 UI 版本发布：

- `applicationId` 必须保持 `com.alicia.cloudstorage.phone`。
- versionCode 必须递增。
- versionName 必须更新。
- Release 必须使用当前正式包同一签名。
- 打包后用 `apksigner verify --print-certs` 对比新旧 APK 证书 SHA-256。
- 上传后台版本管理前，先在已安装旧版的设备上执行覆盖安装验证。

如果作为并行体验版：

- 使用 `applicationId = "com.alicia.cloudstorage.phone.add"`。
- 可以复用同一签名，但不会覆盖旧 App。
- Add 版保留内置更新检测，用于验证完整启动流程；如果未来后台区分包渠道，再按渠道返回对应安装包。
- 应用显示名应和正式版区分，例如 `Alicia 云盘 Add`。

## 27. 验收清单

视觉验收：

- 首页、文件页、传输页、我的页均为白底轻卡片风格。
- 不出现机甲风资源、深色网格背景、金属边框。
- 主色蓝一致。
- 字体层级清楚，文本不重叠。
- Bottom sheet 圆角和高度与参考图一致。

交互验收：

- 文件夹点击主体进入。
- 文件点击主体预览。
- 选择框可多选。
- 多选后批量操作可用。
- FAB 打开上传/新建面板。
- 筛选可重置和确定。
- 下载失败可重新下载。
- 上传/下载进度进入传输列表。

安全验收：

- 重试不复用旧签名 URL。
- 不持久化 token 到传输任务。
- 删除/退出/切环境二次确认。
- 分享保存仍校验权限。
- 下载文件夹仍走后端 ZIP 权限校验。

工程验收：

- `:app:compileDebugKotlin` 通过。
- `:app:assembleDebug` 通过。
- Release 签名证书与当前正式包一致。
- 真机安装覆盖旧版成功。
- 主流程登录、上传、下载、分享、预览、回收站均可用。
