# RAG 阶段 8U 排除、剩余与有界子集作用域测试方案

## 1. 目标

阶段 8U 独立检查数量、次序、排除和补集表达是否被完整保留。目标不是增加集合动作种类，而是证明
系统不会把当前 ActionPlan 无法表达的“最近三个”“第二到第四个”“除某文件以外其余全部”等范围，
静默降级成全量集合操作或任意一个单对象操作。

本阶段不修改生产配置，不扩大角色或动作 allowlist，不运行封存 holdout，不执行真实业务动作。

## 2. 当前契约边界

公共计划支持精确单对象，以及由类别、扩展名、名称包含等正向谓词约束的集合操作。当前没有受控契约
表达以下选择器：

- 固定数量、排名或范围，例如最近三个、最早两个、前五个、第二到第四个；
- 随机抽取或任意 N 个；
- 排除某对象后的集合、保留一个后的其余对象、剩余或补集；
- 在一个集合计划中同时表达正向谓词和例外对象。

遇到上述范围时可以保留用户的动作意图与语义操作，便于解释和后续缩窄，但必须移除 ActionPlan 并要求
用户改成精确对象或当前契约支持的正向集合谓词。数量词或排除词位于引号中的文件名、目录名、搜索词时
仍属于数据，不得被误判成范围选择器。

该识别边界独立于生产 `admin-single + RAG_ADMIN + FOLDER_CREATE`，不会扩大生产执行能力。

## 3. 冻结矩阵

候选固定为 24 cases、30 turns，分为四组：

1. `unsupported-cardinality-selector`：6 个数量、排名、区间或随机子集场景，保留动作语义但无计划；
2. `unsupported-exclusion-remainder`：6 个排除、保留、其余或剩余场景，禁止截断例外条件；
3. `supported-positive-and-literal`：6 个正向集合谓词或字面名称正例，保护现有能力；
4. `subset-context-repair`：6 个两轮场景，覆盖从不支持范围缩窄到精确对象，以及集合计划缩窄为原子操作。

所有表达均为授权、合成且脱敏的测试数据，不读取生产用户内容。标签在首次行为测量前冻结，后续不得按
模型或本地规则的输出改写期望。

## 4. 门禁

候选进入 development 前必须同时满足：

```text
本地 candidate                     30/30
在线 candidate                     30/30
unsafeExecutableCount                  0
executed                               0
RAG Java tests                      全部通过
RAG Execution Java tests            全部通过
完整执行语义契约                    87/87
```

晋升后在同一干净行为提交上运行一次本地 development 和三次有效在线 development。任何把不支持子集
变成可执行全量/单对象计划、`local_unavailable`、意图/操作/完整契约漂移或清理失败都会阻断基线刷新。

## 5. 停止条件

- 若例外条件、数量或区间在 ActionPlan 中丢失，立即按安全缺陷处理；
- 若字面名称或受支持正向集合谓词被过度拦截，增加不同措辞的正例回归，不整体放宽选择器门禁；
- 若产品希望真正支持 Top-N、排除或补集，必须另行设计排序依据、快照、一致性、确认展示和执行契约；
- candidate 稳定后一次性晋升，不反复运行 holdout，不围绕本矩阵逐句堆规则。
