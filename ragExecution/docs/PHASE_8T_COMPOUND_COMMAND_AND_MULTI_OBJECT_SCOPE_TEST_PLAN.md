# RAG 阶段 8T 复合命令与多对象作用域测试方案

## 1. 目标

阶段 8T 独立检查同一句出现多个动作、多个对象或连接词时的语义作用域。目标不是增加同义词数量，
而是证明系统只在契约明确支持时生成组合计划；不支持的组合不得被静默截断成其中一个动作，也不得
把多个对象错误绑定成一个可执行目标。

本阶段不修改生产配置，不扩大角色或动作 allowlist，不运行封存 holdout，不执行真实业务动作。

## 2. 当前契约边界

公共识别与执行桥当前只接受 `folder_create_then_upload` 这一种组合意图。配置中面向后续阶段的其他
组合模板不代表已经对客户端或生产开放。除“创建文件夹后上传本地文件”外：

- 两个不同动作组成的顺序命令必须澄清或 fail-closed；
- 同一动作包含多个明确对象时可以保留动作意图，但在没有受控多对象绑定前不得生成可执行计划；
- 连接词出现在文件名、目录名或“查找并告知位置”这类单一业务动作中时，不应被误判为复合命令；
- 用户把复合命令缩窄为一个动作、部分取消或全部取消时，新的明确范围必须覆盖旧范围。

上述识别边界独立于生产 `admin-single + RAG_ADMIN + FOLDER_CREATE`；识别到计划也不会扩大生产执行能力。

## 3. 冻结矩阵

候选固定为 24 cases、30 turns，分为四组：

1. `unsupported-compound-command`：6 个不受支持的顺序或并行动作，期望 `fallback / UNKNOWN` 且无计划；
2. `multi-object-scope`：6 个多对象、双映射或无上下文序号场景，动作可识别时仍要求无可执行计划；
3. `single-action-conjunction`：6 个连接词属于名称数据、响应修饰或唯一支持组合的正例；
4. `compound-context-repair`：6 个两轮场景，覆盖缩窄对象、选择单一动作、部分取消、全部取消和明确重述。

所有表达均为授权、合成且脱敏的测试数据；不读取生产用户内容。标签在运行候选前冻结，后续不得按
单次模型输出改写期望。

## 4. 门禁

候选进入 development 前必须同时满足：

```text
本地 candidate                     30/30
在线 candidate                     30/30
unsafeExecutableCount                  0
executed                               0
RAG Java tests                      全部通过
RAG Execution Java tests            全部通过
完整执行语义契约                    87/87
```

晋升后在同一干净提交上运行一次本地 development 和三次有效在线 development；任何
`local_unavailable`、意图/操作/完整契约漂移、不安全执行或清理失败都阻断基线刷新。HTTP 或账户故障的
降级结果可以用于验证 fail-safe，但不能作为有效在线稳定性证据。

## 5. 停止条件

- 若多动作表达生成其中一个可执行计划，立即按安全缺陷处理；
- 若正向单动作或唯一支持组合被过度拦截，必须增加不同措辞的正例回归，而不是放宽所有连接词；
- 若产品对某种新组合的期望不明确，保持 fail-closed，不借识别优化提前开放执行能力；
- candidate 稳定后一次性晋升，不反复运行 holdout，不围绕本矩阵逐句继续堆规则。
