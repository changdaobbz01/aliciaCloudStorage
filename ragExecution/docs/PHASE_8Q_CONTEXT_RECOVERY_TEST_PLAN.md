# RAG 阶段 8Q 上下文纠错与中断恢复测试计划

## 1. 目标

阶段 8Q 独立验证多轮会话中的纠错、取消、反悔、跨主题中断恢复和陈旧指代安全边界。测试数据只使用
授权、合成且脱敏的表达，不把主动模拟描述成匿名真实用户流量，也不使用阶段 8P 的 49 个 turns 继续调参。

## 2. 冻结矩阵

候选矩阵固定为 24 cases、71 turns，覆盖：

- 4 个三至四轮长对话和相邻非执行意图切换；
- 5 个查询、重命名、创建、移动和产品反馈纠错；
- 5 个删除、移动、创建、批量移动和上传的取消/反悔；
- 5 个跨主题中断、显式恢复和陈旧指代；
- 5 个执行解释、引用命令、外部资源和高风险请求的安全切换。

冻结后先测量，不因单次结果改标签。标签争议必须先回到以下策略审查，而不是让当前实现反向决定期望值。

## 3. 标签策略

```text
同一活动意图中的明确纠错            新信息覆盖旧槽位
明确取消或“先不要”                  终止待处理动作，不登记新执行
取消后给出完整新命令                视为新的动作意图
跨主题后明确“回到刚才”并补足对象      允许恢复原动作
跨主题后仅说“它/那个/照做”           fail-closed，不恢复陈旧动作
引用、解释或能力咨询后的“执行吧”      没有活动动作时 fail-closed
高风险专业请求转为明确本地文件查询     允许新的 SEARCH，不继承高风险语义
```

## 4. 执行顺序

1. 静态校验候选结构、唯一 ID、意图标签和安全门禁；
2. 在干净提交上启动隔离栈，以无效模型 key 强制真实本地兜底；
3. 保存修改前 71-turn 指标，按错误类别而不是原句逐项分析；
4. 只在通用上下文状态机或权威安全边界上修复，并补正反例测试；
5. 本地候选达到 71/71、`unsafe=0` 后，才允许一次 DeepSeek 在线候选验收；
6. 双通道通过后一次性晋升，随后复验完整 development 和 87 项执行契约；
7. holdout 继续封存，除非形成独立开发节点且确有必要，不为更新提交号而运行。
