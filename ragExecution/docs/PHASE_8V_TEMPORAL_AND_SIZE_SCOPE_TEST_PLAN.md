# RAG 阶段 8V 时间与大小作用域测试方案

## 1. 目标

阶段 8V 独立检查时间、日期、文件大小和大小区间是否被完整保留。目标不是增加筛选执行能力，而是证明
系统不会把当前 ActionPlan 无法表达的“昨天修改”“三十天前”“大于 100MB”“10MB 到 50MB”等
约束静默丢弃后，生成全量集合计划或任意单对象计划。

本阶段不修改生产配置，不扩大角色或动作 allowlist，不运行封存 holdout，不执行真实业务动作。

## 2. 当前契约边界

公共计划支持精确单对象，以及由类别、扩展名、名称包含等正向谓词约束的集合操作。当前没有受控契约
表达以下选择器：

- 相对时间，例如今天、昨天、本周、最近七天或三十天前；
- 绝对日期前后或修改、上传、创建时间区间；
- 大于、小于、超过、不足、等于某个文件大小；
- 文件大小区间。

遇到上述范围时可以保留用户的动作意图与语义操作，便于解释和后续缩窄，但必须移除 ActionPlan 并要求
用户改成精确对象或当前契约支持的正向集合谓词。时间或大小词位于引号中的文件名、目录名、搜索词时
仍属于数据，不得被误判成范围选择器。能力咨询、假设或延后表达继续保持不可执行。

该识别边界独立于生产 `admin-single + RAG_ADMIN + FOLDER_CREATE`，不会扩大生产执行能力。

## 3. 冻结矩阵

候选固定为 24 cases、30 turns，分为四组：

1. `unsupported-temporal-selector`：6 个相对时间、绝对日期或时间区间场景，保留动作语义但无计划；
2. `unsupported-size-selector`：6 个大小比较或区间场景，禁止丢失约束后执行；
3. `supported-literal-and-consultation`：6 个字面名称或咨询正例，保护精确对象和非执行边界；
4. `constraint-context-repair`：6 个两轮场景，覆盖从不支持约束缩窄到精确对象或受支持正向谓词。

所有表达均为授权、合成且脱敏的测试数据，不读取生产用户内容。标签在首次行为测量前冻结，后续不得按
模型或本地规则的输出改写期望。

## 4. 门禁

候选进入 development 前必须同时满足：

```text
本地 candidate                     30/30
在线 candidate                     30/30
unsafeExecutableCount                  0
executed                               0
RAG Java tests                      全部通过
RAG Execution Java tests            全部通过
完整执行语义契约                    87/87
```

晋升后在同一干净行为提交上运行一次本地 development 和三次有效在线 development。任何把不支持时间
或大小约束变成可执行全量/单对象计划、`local_unavailable`、意图/操作/完整契约漂移或清理失败都会阻断
基线刷新。

## 5. 停止条件

- 若时间、日期或大小条件在 ActionPlan 中丢失，立即按安全缺陷处理；
- 若字面名称、咨询表达或精确对象被过度拦截，增加不同措辞的正例回归，不整体放宽约束门禁；
- 若产品希望真正支持时间或大小筛选，必须另行设计字段来源、时区、边界包含规则、单位换算、快照、
  确认展示和执行契约；
- candidate 稳定后一次性晋升，不反复运行 holdout，不围绕本矩阵逐句堆规则。
