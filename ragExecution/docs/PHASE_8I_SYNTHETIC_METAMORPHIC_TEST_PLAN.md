# RAG 阶段 8I 独立拟真表达与变形测试计划

## 1. 目标

项目仍处于开发阶段，暂时没有足量、经过授权且可脱敏的真实用户语料。阶段 8I 不等待不存在的
生产数据，也不把模型随机生成的句子直接当作真实分布，而是建立可审查的独立拟真候选集，验证
识别系统在语义保持和语义翻转条件下是否稳定。

## 2. 设计原则

1. 先定义能力边界和期望标签，再运行当前实现；失败后不得反向修改标签迎合结果。
2. 不读取或改写现有 holdout 原句，不用 holdout 驱动候选设计。
3. 使用最小对照：只改变一个关键因素，观察意图是否按预期保持或翻转。
4. 执行请求与咨询、引用、风险分析必须分离；非执行话语不得生成可执行计划。
5. 集合与原子选择器必须分离；提高集合召回率不能吞掉单文件和明确命名对象。
6. 所有评测只登记并清理未确认任务，禁止确认或执行真实业务动作。
7. 候选先通过本地回退和 DeepSeek 在线两条通道，再允许晋升开发集。
8. 开发节点关闭前不运行 holdout；晋升后最多按治理流程运行一次最终泛化检查。

## 3. 首批候选矩阵

```text
执行 / 咨询 / 引用边界                 4
集合 / 原子最小对照                    8
名称、扩展名、前缀谓词变形             3
空白噪声、括号命名、自然搜索、组合操作  5
总计                                  20
```

首批同时包含一个常见错字候选，用来检查系统是否能在不扩大模糊匹配风险的前提下处理低成本拼写噪声。

## 4. 门禁

```text
unsafeExecutableCount          必须为 0
missingResponseCount           必须为 0
infrastructureFailures         必须为 0
候选本地回退完整契约           必须全部通过
候选 DeepSeek 在线完整契约     必须全部通过
RAG Java 回归                  必须通过
87 项执行语义契约              必须保持基线一致
```

出现错误时只按结构类别修复，并补充正反测试。不得扩大生产角色、动作白名单或确认权限。
