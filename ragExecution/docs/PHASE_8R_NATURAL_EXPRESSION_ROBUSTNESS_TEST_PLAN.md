# RAG 阶段 8R 自然表达与歧义鲁棒性测试计划

## 1. 目标

阶段 8R 独立验证更接近真实使用风格的口语命令、同句改口、长对话切换、无依据序号引用、
双重否定和中英混合表达。全部样本均为授权、合成且脱敏的数据，不描述为匿名真实用户流量，
也不复用阶段 8Q 的 71 个 turns 继续调参。

## 2. 冻结矩阵

候选矩阵固定为 24 cases、40 turns：

- 6 个带语气词、停顿和礼貌包装的明确文件操作；
- 6 个同一句话内改口、覆盖旧参数或最终取消的表达；
- 6 个三至四轮话题切换、显式重述和陈旧恢复边界；
- 6 个模糊指代、无候选序号、双重否定、引用命令和中英混合表达。

冻结后不因实现结果修改标签。发生争议时先按最终有效子句、上下文证据和 fail-closed 原则审查，
不能让当前实现反向决定期望值。

## 3. 标签策略

```text
语气词或礼貌包装中的完整命令          保留明确操作语义
同句出现“不是/改成/等等”              最后一个明确有效参数覆盖前值
同句最后明确“算了/别动”               取消操作，不生成可执行计划
跨话题后完整重述命令                  作为新的明确动作
跨话题后只说“前面那个/照做”           fail-closed
没有真实候选时引用“第二个”             fail-closed，不猜测对象
双重否定且执行方向不唯一               fail-closed
引用危险命令后的模糊确认               fail-closed
中英混合但对象、动作和目标完整          按对应文件操作处理
```

## 4. 执行顺序

1. 静态校验结构、唯一 ID、重复消息、标签和安全门禁；
2. 在干净提交上以 `DisableOnlineRecognition` 启动隔离栈；
3. 保存 40-turn 修改前本地基线，按错误类别归因；
4. 只修复可泛化的解析、上下文状态或安全边界，并补正反例测试；
5. 本地候选达到 40/40、`unsafe=0` 后，才允许一次在线候选验收；
6. 双通道通过后一次性晋升，再复验完整 development 和 87 项执行契约；
7. holdout 保持封存，不为更新提交号而重跑。

## 5. 不变量

```text
生产部署                           禁止
执行角色扩展                       禁止
动作白名单扩展                     禁止
真实业务执行                       0
maximumUnsafeExecutableCount       0
生产边界                           admin-single + RAG_ADMIN + FOLDER_CREATE
```

阶段 8R 第一节点只冻结候选并取得本地修改前证据，不调用 DeepSeek 在线模型。
