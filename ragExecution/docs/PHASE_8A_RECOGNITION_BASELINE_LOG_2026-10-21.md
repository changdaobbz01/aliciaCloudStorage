## 3. 本轮发现并处理的安全问题

首次保留集运行中，产品体验反馈被错误识别为文件分享并生成 `share` 动作草稿。该响应没有后端可执行草稿、没有任务引用、没有真实执行，但会把非执行反馈错误带入文件操作确认流程，因此安全门禁正确拒绝了基线。

修复采用泛化规则：只有同时出现产品能力词和明确改进愿望表达时，才优先识别为产品反馈。另加入不同措辞的开发集与 Java 回归用例。修复后：

```text

保留集 unsafeExecutableCount = 0

```

## 4. 评测框架边界

- `recognition-dev.json` 用于错误分类和定向优化。
- `recognition-holdout.json` 只在一个开发批次完成后检查泛化。
- 准确率不达标会被记录，但不会伪装成基础设施故障。
- API/清理失败、缺失响应和不安全可执行计划会直接失败。
- 每份报告记录源码提交、工作树洁净度和数据集 SHA-256。
- 基线写入脚本拒绝脏源码、混合识别来源和覆盖已有基线。
- 现有 `contract-baseline.json` 继续锁定 87 项执行语义，不能因识别调优而放宽。

## 5. 下一步

下一批只使用开发集处理当前主要错误类别：

1. 写作与生活服务边界表达不足。
2. 能力询问和闲聊同义表达不足。
3. 产品反馈与上传、分享动作的路由冲突。
4. 自然目录列举与普通搜索的语义操作混淆。
5. 缺少源对象时，删除、移动和重命名意图过早退化为 fallback。

每一批优化完成后先运行开发集、Java 回归和 87 项契约门禁，再单次运行保留集。DeepSeek 恢复可用后单独建立 `deepseek-online` 基线，不与本地兜底基线混合。

生产继续保持：


本阶段未部署生产，也未扩大角色、动作、批量或组合执行能力。
